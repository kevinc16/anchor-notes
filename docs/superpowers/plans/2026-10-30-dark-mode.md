# Dark Mode Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement issue #79: System (default), Light, and Dark across extension-owned UI, including live changes and persisted overrides.
**Architecture:** Normalize a theme preference in existing settings. A small shared browser lifecycle observes storage and matchMedia, applying resolved theme attributes to extension roots only. Reuse Tailwind and scoped content CSS tokens; keep highlight readability independent from the chosen extension theme.
**Tech Stack:** Existing WXT, React, TypeScript, Tailwind, Vitest and Playwright; native browser APIs; no new dependencies.
**Spec:** https://github.com/kevinc16/anchor-notes/issues/79

## Global Constraints
- Keep notes, anchoring, privacy, and schema version compatible.
- Restore imported settings separately in #132; exports preserve theme and old local data defaults to System.
- Never theme host html/body; content UI and highlight styling remain scoped.
- Use Node 24.22.1+ within 24.x; run all issue-required checks and distinguish automated Chromium from manual Chrome/Firefox verification.

## Review Focus
- Existing editor text/focus must survive live theme changes.
- Explicit overrides must ignore OS changes; System must respond immediately.
- Initial storage reads must not overwrite a newer storage event.
- Dialogs and hardcoded interactive states must maintain contrast.
- Host page theme is independent of extension theme, including all four highlight colors.
